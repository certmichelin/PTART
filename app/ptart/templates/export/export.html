Full export

Creates a portable ZIP containing legacy.sqlite3 and media/ for migration. Includes users, password hashes, 2FA seeds, raw API tokens, catalogs, team roles, archived projects, findings in every status, flags, assets, retests, screenshots and attachments. Primary keys and column names match the legacy database.

This archive contains credentials. It includes password hashes, TOTP secrets and API token material. Store it like a database backup, transfer it over a trusted channel, and delete copies once the migration is verified.

Pause all other writers and media edits before the final export. The database is read from one snapshot, but files on disk cannot be frozen. Generation runs synchronously and large installations may need increased server timeouts and temporary disk space for the database and ZIP.

Missing evidence files or unapplied migrations refuse the export. A manifest.json lists row counts, column names and database/media SHA-256 checksums. This migration input is not a full Django restore backup: sessions, Django permissions, settings and generated reports are not included. On a fresh PTART instance, apply migrations then run python manage.py import_archive /path/to/export.zip on the server, before creating users or loading catalogs. Existing data is never merged or overwritten. See docs/MIGRATION_EXPORT.md for the procedure and limitations.
